# CONTRACTv1.3 - архитектурный и data-контракт проекта

Файл: `docs2/CONTRACTv1.3.md`

Эта версия дополняет `CONTRACTv1.2.md`:
- `legacy` окончательно выводится из активного планирования;
- `core` фиксируется как единственный рабочий контур;
- режим критика и агентный протокол считаются частью обязательного контекста.

## 0. Что считается обязательным чтением

Перед работой с проектом нужно прочитать:
- `docs2/policies/PROJECT_RULES_v1.1.md`
- `docs2/operations/MIGRATION_CONTEXT_v1.3.md`
- этот контракт

## 1. Главная рамка

- `core` является главным и единственным объектом развития;
- `legacy` остается только как архивный reference;
- sandbox - промежуточный этап к online;
- offline/online рассматриваются как единая исследовательская траектория;
- source of truth для договоренностей строится через `docs2`.

## 2. Правила как часть контракта

Правила из `PROJECT_RULES_v1.1.md` считаются частью обязательного контекста контракта.
Это включает:
- patch discipline;
- directory discipline;
- CLI discipline;
- versioning discipline;
- migration discipline;
- LLM discipline;
- critic mode discipline;
- agent iteration discipline.

## 3. Что не может быть нарушено

- нельзя тратить отдельный roadmap-ресурс на сравнение с `legacy`;
- правила проекта не могут игнорироваться "потому что это не контракт";
- новый чат не может пропускать этап чтения правил;
- нельзя обнулять старую документацию при выпуске новой версии;
- нельзя перестраивать архитектуру молча через патчи.

## 4. Агентный режим для этапа 1.1

Для этапа 1.1 допустим только короткий итерационный протокол:
- шаги по 1-2 действия;
- сначала фактическая проверка `app2`, потом предложение патча;
- каждый шаг имеет критерий приемки и stop-condition;
- следующий шаг не начинается, если предыдущий не закрыт по self-check.
