# LLM_WORKFLOW_v1.0 - роли ChatGPT, Qwen и локальных LLM-агентов

## 0. Назначение

Этот документ фиксирует:
- кто какую роль играет;
- как внешние предложения попадают в проект;
- как использовать agent mode без обхода patch discipline;
- какие риски у локальных LLM-агентов и bridge-слоёв нужно учитывать заранее;
- что новый чат обязан сделать до анализа `app2`.

Если workflow пересекается с `PROJECT_RULES_v1.0.md`, источник истины - полный свод правил проекта.

## 1. Что обязан сделать новый чат

1. Прочитать:
   - `docs2/policies/PROJECT_RULES_v1.0.md`
   - `docs2/operations/MIGRATION_CONTEXT_v1.0.md`
   - `docs2/READMEv1.0.md`
   - `docs2/CONTRACTv1.0.md`
   - `docs2/model_plan_v1.0.md`
2. Подтвердить понимание правил.
3. Кратко восстановить стадию проекта и активные риски.
4. Только потом переходить к анализу `app2`, roadmap и патчам.

## 2. ChatGPT

Роль:
- архитектурный анализ;
- roadmap;
- contracts / docs;
- патчи по согласованному ТЗ;
- критическая ревизия решений.

Обязанности:
- опираться на source-of-truth docs;
- не терять смысл уже зафиксированных решений;
- явно говорить, если файла нет или версия сомнительна;
- отвечать в режиме критика.

Ограничения:
- не меняет контракт молча;
- не считается источником истины без фиксации в docs;
- не может обходить patch discipline.

## 3. Qwen

Роль:
- локальный debugger;
- внешний reviewer;
- генератор гипотез и контраргументов;
- быстрый анализ файлов и трейсов.

Ограничения:
- не является source of truth;
- не утверждает архитектурные решения без фиксации в docs;
- его выводы рассматриваются как вход для обсуждения, а не как автоматическое решение.

## 4. Локальные LLM-агенты и bridge-слои

Роль:
- bridge к локальной модели;
- вспомогательные аналитические инструменты для диагностики, review и локальной отладки;
- ускорение гипотез и проверки файлов, но не замена source of truth.

Текущий принцип:
- конкретная реализация локального агента может меняться;
- по умолчанию любой такой агент считается read-only, если иное не зафиксировано отдельно;
- наличие bridge-слоя не даёт права обходить patch discipline.

Разрешено:
- чтение файлов и каталогов;
- сбор наблюдений;
- формулирование гипотез и замечаний по коду и архитектуре.

Запрещено:
- скрытые правки проекта;
- обход review/patch workflow;
- изменение docs или контракта без отдельного решения;
- подмена зафиксированных правил локальными удобствами конкретного агента.

Риски, которые должны учитываться заранее:
- несинхронность source of truth между чатом, кодом и локальным агентом;
- скрытые изменения или неявные side effects;
- выдача архитектурных рекомендаций без фиксации в docs2;
- ложное ощущение, что локальный агент сам по себе является авторитетом по проекту.

## 5. Как идеи попадают в проект

1. внешняя модель / аналитик / LLM даёт идею или критику;
2. идея обсуждается;
3. если принята, фиксируется в docs2 или в текущем контракте;
4. затем только идёт патч;
5. при необходимости обновляется migration context.

## 6. Что нельзя делать

- сокращать правила до 3-4 пунктов, если проект уже имеет длинный набор договорённостей;
- считать миграционный пакет полным без переноса правил;
- предлагать патчи без чтения docs2 source of truth;
- приписывать любому локальному агенту полномочия на скрытую запись в проект.
